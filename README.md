# JAZZ Assets

> Технический пакет ресурсов JAZZ. Самостоятельная игра не поддерживается.

`jazz_assets` поставляет визуальный слой [JAZZ — Tactical Overhaul](../jazz/README.md): Entity, модели, материалы, текстуры и связанные ресурсы, которые используют core, maps и units.

| Свойство | Значение |
| --- | --- |
| Mod ID | `pDGDhr` |
| Автор metadata | `Doctor_Leevsy` |
| Роль | Визуальные ресурсы и EntityData |
| Самостоятельная установка | Не поддерживается |

## Что находится в пакете

- Entity и ресурсы оружия, магазинов, прикладов, сошек, прицелов и других компонентов;
- meshes, materials, textures и состояния моделей;
- spots и варианты Entity, используемые предметами и персонажами;
- пути ресурсов вида `Mod/pDGDhr/...`, на которые ссылаются соседние пакеты.

Публичный контракт пакета — стабильные имена EntityData, states, spots и resource paths. Их переименование требует поиска ссылок во всех четырёх репозиториях.

## Граница ответственности

Пакет не владеет боевыми формулами, балансом оружия, картами или UnitData. Поведение предметов находится преимущественно в `jazz`; владельцы карт и юнитов — `jazz-maps` и `jazz-units`.

## Установка

Для поддерживаемой конфигурации нужны:

1. последняя опубликованная версия [`JA3_CommonLib`](https://gitlab.com/injto4ka/ja3_commonlib);
2. `JAZZ Assets`;
3. `JAZZ Units`;
4. `JAZZ Maps`;
5. основной `JAZZ`.

Неполный комплект и старые версии CommonLib не поддерживаются.

## Разработка

Entity Lua и бинарные ресурсы должны изменяться согласованно через Mod Editor и asset pipeline. Экспорт является инкрементальным и не удаляет устаревшие части автоматически; после re-export/re-import требуется проверка в новом процессе игры.

В legacy-описаниях присутствуют абсолютные пути к исходным FBX с прежних рабочих машин. Это известный технический долг, а не шаблон для новых ресурсов; полная пересборка всего художественного pipeline только из содержимого репозитория пока не гарантируется.

Перед удалением или переименованием Entity проверяйте наследование, states, spots, оружейные компоненты и ссылки из остальных пакетов. Runtime-проверка должна включать предмет в руках, на земле и во всех используемых состояниях компонентов.
